# Заготовка: читалка на одном NSTextView

Разведка к переносу слоя отрисовки с SwiftUI на TextKit. Отдельный пакет,
в сборку приложения не входит.

```bash
cd experiments/textkit-reader && swift run
PROBE_CHECK=1 swift run   # проверки без мыши, печатает и выходит
```

## Зачем

В нынешней читалке документ — стопка отдельных SwiftUI-вью, по одной на абзац.
Из этого следуют два дефекта, которые иначе не лечатся: выделение не переходит
между абзацами и курсор не становится рукой над ссылкой. Оба упираются в то,
что и выделение, и отслеживание курсора в SwiftUI живут внутри одной вью.

## Что проверено

- **Выделение через весь документ** — работает: одно текстовое хранилище, драг от
  заголовка до последнего абзаца берёт всё вместе со списками, цитатой и кодом.
  Без мыши это же видно в `PROBE_CHECK`: диапазон поперёк границы абзацев
  возвращает текст из обоих.
- **Разбор markdown** идёт через `swift-markdown` (тот же cmark-gfm, что под
  MarkdownUI), то есть это работающий скелет конвертера, а не заглушка.
- **Значения темы** сняты с `Sources/MDReader/Theme.swift`: масштабы шести
  заголовков, отступы, межстрочный интервал, ширина маркеров.
- **Украшения, которых в TextKit нет** — полоска цитаты и скруглённая подложка
  кода: прямоугольник диапазона берётся через `enumerateTextSegments`, рисуется
  в `draw`. Важно: **не** в `drawBackground` — при `drawsBackground = false`
  AppKit туда не заходит, и первая версия молча ничего не рисовала.

## Что не проверено и не сделано

- Курсор-рука над ссылкой: атрибут `.link` и `.cursor` в `linkTextAttributes`
  проставлены, глазами не подтверждено.
- Таблицы и картинки — строки-заглушки. План: вложение `NSTextAttachment` с
  нынешней SwiftUI-вёрсткой внутри; выделение сквозь него проходит, потому что
  для хранилища вложение — один символ.
- Совпадение с нынешним видом **не достигнуто и само не получится** — это и есть
  основная работа переноса, сверять замером высоты, как в `docs/testing.md`.
