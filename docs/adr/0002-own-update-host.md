# 0002. Обновления со своего домена, а не с GitHub

Дата: 18–19.08.2026

## Контекст

Первая версия проверки обновлений ходила в GitHub Releases API. Это работало, но
привязывало установленные копии к внешнему сервису и к конкретному репозиторию.

## Решение

Фид и образы переехали на `md.dmind.pro` — домен проекта, раздаётся Caddy с
машины Zomro.

Ключевое: приложение знает **домен**, а не адрес машины. Сервер можно
переставить, перенаправив DNS, и все установленные копии продолжат обновляться.

Формат фида намеренно минимальный: `version`, `url`, `notes`.

## Последствия

Публикация выпуска — теперь свои три команды (`docs/runbooks/release.md`), а не
кнопка на GitHub.

Одна копия 1.5.0 успела уйти с проверкой на GitHub, поэтому там же опубликована
1.5.1 — как мостик, чтобы она перешла на новый источник. Дальше выпуски только на
свой сервер.

Появилась своя статистика — на GitHub её не было.

## Альтернативы

**Sparkle.** Стандарт для macOS, умеет ставить обновления сам и проверять
подписи. Отвергнут: тянет зависимость и всё равно упирается в отсутствие
Developer ID, а нужное поведение уместилось в один файл.
