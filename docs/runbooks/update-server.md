## Блок в Caddyfile

Конфиг общий для десятка сайтов, поэтому: копия, правка, `caddy validate`, и
только потом перезагрузка.

```bash
ssh dmind 'cp /etc/caddy/Caddyfile ~/Caddyfile.backup-$(date +%Y%m%d-%H%M%S)'
# ... правка ...
ssh dmind 'caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile'
ssh dmind 'sudo -n systemctl reload caddy'
```

Перезагрузка Caddy разрешена без пароля, правка Caddyfile — тоже (файл
`rw-rw-rw-`). Полный sudo требует пароля.

После перезагрузки проверить соседей, а не только свой сайт:

```bash
ssh dmind 'for h in dmind.pro m.dmind.pro hq.dmind.pro md.dmind.pro; do
  printf "%-16s %s\n" "$h" "$(curl -s -o /dev/null -w "%{http_code}" https://$h/)"; done'
```

## Две грабли, стоившие простоя

**`caddy validate` выполняется от того, кто его запустил.** Если в конфиге путь к
журналу, куда может писать только Caddy, валидация падает по правам — и, что
хуже, **создаёт файл журнала с чужим владельцем**. После этого настоящий Caddy не
может в него писать и зависает в состоянии `reloading`, унося с собой все сайты
на машине. Поэтому журнал лежит в каталоге, доступном обоим, а не в
`/var/log/caddy`.

**Caddy создаёт журналы с правами 0600** независимо от ACL каталога. Чтобы файл
можно было прочитать, в блоке нужен явный `mode 644`.

## Статистика

```bash
ssh dmind '~/md-stats'      # за всё время
ssh dmind '~/md-stats 7'    # за последние 7 дней
```

Скачивания и проверки обновлений считаются раздельно: проверка — это не загрузка.
Скачиванием считается только реально отданный файл (код 200 или 206 при докачке).
Показывает: сколько всего, с каких адресов, по каким версиям, последние загрузки.

Журнал ротируется по 20 МБ, хранится шесть файлов; сжатые скрипт тоже читает.

Копия скрипта и блока конфига — в `server/` репозитория.
