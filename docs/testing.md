# Проверки и тесты

Xcode-проекта нет, поэтому XCTest не используется. Проверки двух видов: чистые
функции — отдельными харнессами, вёрстка и раскладка — замерами в работающем
приложении.

## Чистые функции

Логику, которую нельзя проверить глазами, выносим в тип без SwiftUI и компилируем
вместе с крошечным `main.swift`:

```bash
swiftc -O Sources/MDReader/TabSplit.swift main.swift -o t && ./t
```

Что покрыто:

| Что | Файл | Случаев |
|---|---|---|
| Распределение вкладок и переполнение | `TabSplit` | 18 |
| Резка markdown на блоки | `MarkdownBlocks` | 14 |
| Сравнение версий | `UpdateChecker.isNewer` | 15 |
| Формат процента и разбор ввода | `PercentFormat` | 9 |

Показательные случаи: `1.10` новее `1.9` (строковое сравнение сказало бы
обратное); рыхлый нумерованный список не должен распасться на несколько списков;
активная вкладка не должна уезжать в переполнение.

Локализация проверяется скриптом, который вытаскивает из исходников все
локализуемые литералы и сверяет с таблицей: ключей поровну, пропущенных и лишних
нет.

## Вёрстка — замером, а не на глаз

`ScrollView` умеет сообщить высоту содержимого. Временная проба под
`MDREADER_PERF=1` печатает её в stderr, и документ известной структуры даёт
число, которое можно сравнить с ожидаемым.

**Суммарная высота — плохая проверка сама по себе.** Один раз она совпала при
полностью поехавшем распределении: сколько потерялось между абзацами, столько же
прибавилось над заголовками. Заголовки прилипли к тексту, абзацы слиплись, а
итог сошёлся.

Поэтому нужны документы, каждый из которых меряет **одну** величину: двадцать
одинаковых абзацев без заголовков; десять разделов «заголовок + абзац»; двадцать
пунктов списка. Тогда разница делится на число промежутков и сверяется с
значением из темы.

Эталон для сравнения берётся сборкой предыдущей версии в отдельном worktree:

```bash
git worktree add /tmp/old <коммит> && cd /tmp/old && ./build.sh release
```

Так были найдены: потерянные 16 pt между абзацами (304 на 19 промежутках) и
неработающий регулятор отступа между пунктами списка — 6, 12 и 40 давали
одинаковую высоту.

## Раскладка тулбара

Кадры элементов снимаются через `.onGeometryChange(for: CGRect.self)` в
координатах окна. Элемент тулбара и контент делят это пространство — проверено
отдельным харнессом, тулбар отдаёт `y=18`, контент `y=52`.

Что смотреть: правый край кластера должен быть в ~8 pt от края окна; ни один наш
элемент не должен оказаться в системном переполнении
(`toolbar.visibleItems` против `toolbar.items`).

## Состояние, которое переживает перезапуск

Позиция чтения, сессия, недавние файлы. Проверять **двумя прогонами**, а не одной
записью: то, что значение легло в `UserDefaults`, ещё не значит, что оно там
окажется после настоящего выхода, и уж точно не значит, что его прочитают.

1. прогон — открыть документ, довести состояние до нужного, выйти
   (`osascript -e 'tell application "MD Reader" to quit'`, не `pkill`: убийство
   процесса не воспроизводит выход пользователя);
2. `defaults read com.denis.mdreader session.scrollPositions` — что записалось;
3. прогон — запустить снова и замерить, куда встали. Ноль означает, что
   восстановления не было, каким бы правильным ни выглядел ключ в настройках.

Замер на третьем шаге — временной пробой по `MDREADER_SCROLLTEST`, которая пишет
смещение в stderr; убрать до коммита, как и `MDREADER_PERF`.

Грабли, на которые уже наступили: писать состояние только в
`applicationWillTerminate` недостаточно, если в `Info.plist` стоит
`NSSupportsSuddenTermination` — этот ключ разрешает системе убить процесс, не
вызывая обработчик. Оба ключа внезапного и автоматического завершения должны быть
`false`, а состояние дополнительно писаться при потере фокуса.

Настройки у прогонов общие с пользователем — снимать и возвращать снимок
(`defaults export` / `import`), иначе тестовые файлы попадут в его недавние.

## Проверки на сервере

Только с посторонней машины — сам сервер резолвит себя и всегда отвечает:

```bash
ssh praxius 'curl -s -o /dev/null -w "%{http_code} %{ssl_verify_result}\n" https://md.dmind.pro/appcast.json'
```

## Что нельзя проверить отсюда

Доступа к экрану нет, поэтому визуальные вещи и жесты остаются за человеком:
выделение текста мышью, перетаскивание вкладок, вид стекла, попадание цветов.
Если проверка невозможна — это надо сказать, а не выдавать за проверенное.
